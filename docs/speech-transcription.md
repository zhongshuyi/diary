# 离线录音转文字

“设置 → 录音转文字”提供独立的语音识别模型。显式下载 SenseVoice Small int8（约 240 MB），校验完成后可以开启“保存录音后自动转写”。默认关闭自动转写，下载前不访问网络；识别过程不上传录音，也不使用在线日记模型的 API Key。

也可从“我的 → 录音转文字”直达，或在设置搜索“录音”“转写”。该功能随 Android 1.1.0 发布；普通日记仍支持 Android 7.0（API 24），识别能力按下面的系统与架构要求单独启用。

日记保存成功后进入串行转写队列。结果显示在对应录音下方，可以重新转写或取消；识别失败不会丢失原录音，也不改动日记正文。旧录音需要手动点击“转为文字”，开启自动模式不会批量重放全部历史。移除语音模型会关闭自动转写，保留原录音与已有文字。

## 支持范围

- Android 8.1 或更高版本的 ARM64 手机：支持应用的 AAC/m4a 录音及 PCM WAV；Windows x64 Flutter 工程暂支持 WAV。其余架构和平台保留普通日记能力，暂不支持离线识别。Electron 桌面客户端尚未接入识别引擎。
- 支持中文、英语、日语、韩语、粤语；噪声、方言和口音可能影响结果。
- 每段录音不超过 3 分钟、50 MB，超过限制明确报错，不截取剩余内容。每条日记最多保留 32 段转写，每段最多 16,000 字符。
- Android 解码在独立线程，模型加载、PCM 处理与 ONNX 推理在 worker isolate，最多使用 2 个 CPU 线程。转写与本地文字模型串行使用推理资源；键盘切换时延后启动，切换后台取消待处理任务。当前分段识别结束后释放取消任务的原生资源。

## 数据与搜索

`audioTranscripts` 作为录音附件的派生文字保存，按 `audioPaths` 顺序关联。它不替换 `content` 或 `contentText`，不改变日记时间或气泡顺序。时间线搜索和数据库搜索可以匹配转写文字。删除、重新排序和跨设备路径重写会维持录音关联，旧格式没有该字段时读取为空。

转写会随既有日记备份与同步传输；启用同步意味着识别后的文字会同步到你的自托管服务器。**跨设备保留转写需要更新同步服务器**，v2 协议新增可选字段，无需改变配置或数据库结构。旧服务器会丢弃未知字段；当前客户端会保留同一录音在本机已经保存的文字，避免旧响应清空它们，但旧服务器无法将转写传到其他设备。在线日记模型接入本身不要求更新同步服务器。

语音模型和识别设置不进入日记同步、ZIP 备份或 Android 系统备份。模型下载使用固定来源、文件大小与 SHA-256，先写临时目录再原子安装；下载失败或取消保留原模型。

## 来源、许可与原生构建

识别使用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 的 SenseVoice API；模型来自 [官方转换仓库](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17)，权重适用 [FunASR 模型协议](https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE)，与项目 MIT 许可分开。下载目录保留作者、来源与协议全文。

Flutter 的平台运行库采用只含 ASR 的构建，关闭 TTS、eSpeak、Piper 等合成组件，避免带入这些组件的额外授权与分发要求；这不改变识别运行库和模型各自的许可。原生库为构建产物，不提交到源码仓库；Windows 主机使用 `tools/build-speech-runtime.ps1` 准备 Android 库，或使用 `python tools/prepare-speech-runtime.py --platform windows` 准备 Windows 库。Linux 的 Android 构建方式见 [原生运行库说明](../mobile/native/offline-speech/README.md)。源版本、依赖摘要与输出清单固定，禁止用带 TTS 的默认二进制替代。原生第三方声明随 APK 分发，可从“关于 → 开源许可证”查看。
