# 手机 App 第一轮交互与动效改造设计

## 目标

把“此刻 · diary”的手机端首要任务从“打开首页后再找到输入框”改为“在任意主页面都能单手留下一个瞬间”，同时让保存、编辑、退出、解锁、删除和导入这些高频或高风险操作拥有明确、可恢复的反馈。

## 范围

第一轮只改造移动端，不改变桌面端壳层和数据模型。范围包括：

1. 全局悬浮速记按钮：可拖拽、可点击、避开底部导航和系统安全区；位置仅保存在本机。
2. 速记面板：从底部弹出，键盘打开时不遮挡输入；保存中禁用重复提交，保存成功后清空并提供本地保存反馈。
3. 编辑器保护：新建和编辑都支持短延迟自动草稿；离开时有未保存内容确认；成功保存后清理草稿。
4. 详情连续性：从详情编辑后返回详情页，而不是直接返回列表；收藏操作有即时视觉反馈。
5. 隐私锁恢复：取消或失败后留在锁屏页，显示原因并允许再次验证，不主动关闭应用。
6. 破坏性操作：移入回收站后提供短时撤销；永久删除展示附件影响；导入备份先展示数量并确认覆盖。
7. 动效基础：统一 150–250ms 的轻量动效，优先使用 opacity、transform、AnimatedSwitcher 和 Flutter 原生 ripple；遵守 `MediaQuery.disableAnimations`。

## 交互设计

### 悬浮速记按钮

- 默认位于主内容区域右下方，距离右边 16dp，距离底部导航上沿 16dp。
- 长按/拖拽移动，位置被限制在内容区域内，不遮挡底部导航；拖拽结束后吸附到最近的左右边缘。
- 点击按钮打开速记 Bottom Sheet；点击区域保持至少 48dp，按钮包含语义标签“快速记录”。
- 速记输入默认为多行文本，提交按钮为“记下”；空内容提交时保留面板并聚焦输入框。
- 面板关闭不丢失本次未提交文本；重新打开前暂存内容仍保留在面板状态中。

### 编辑器草稿与退出

- 标题、正文、编辑方式、分类、标签、心情和附件发生变化后 500ms 无输入即保存草稿。
- 编辑已有记录使用稳定的记录 ID 作为草稿键，新建记录使用统一的新建草稿键。
- 打开编辑器发现非空草稿时显示“恢复草稿”和“丢弃草稿”。
- 关闭编辑器且存在未保存内容时显示确认；保存成功后清理草稿。
- 顶部保存按钮和底部保存按钮保留一个主要视觉动作，另一个只作为一致的辅助入口，不制造两个同等强度的 CTA。

### 反馈和恢复

- 保存成功：列表立即更新，显示“已保存到本机”；失败：保留输入，显示可重试错误。
- 收藏：先更新当前卡片，再异步持久化；图标通过短暂 AnimatedSwitcher 反馈状态变化。
- 移入回收站：立即从当前列表移除，SnackBar 提供 5 秒“撤销”。
- 永久删除：确认文案包含记录名称和附件数量；取消不会改变任何状态。
- 备份导入：解析后先显示记录数量、是否覆盖现有数据，再执行现有替换流程。
- 生物识别失败或取消：停留在锁屏页，显示“验证未完成，请重试”，不退出 App。

## 动效规范

| 场景 | 时长 | 动效 |
| --- | ---: | --- |
| 按钮、收藏、开关反馈 | 150ms | easeOut / AnimatedSwitcher |
| 速记面板打开关闭 | 220ms | Bottom Sheet 原生转场 |
| 页面 push/pop | 240ms | opacity + 轻微横向位移 |
| 列表新增/移除 | 200ms | size + opacity |
| 悬浮按钮吸附 | 180ms | easeOutBack，拖拽时不延迟跟手 |

当 `MediaQuery.disableAnimations` 为 `true` 时，所有自定义动效时长降为 0，不能阻塞输入和导航。

## 视觉边界

- 保留现有纸张、墨色和陶土色品牌方向。
- 第一轮不更换字体、不新增第三方动画库、不重写所有页面。
- 优先减少重复 CTA 和重复页面大标题；卡片和圆角的系统化重构放到下一轮。
- 新增状态文本使用直接、可操作的中文，不用模糊的“出了点问题”。

## 验收标准

- 在时间线、日历、媒体、洞察和我的任一主页面都能找到并使用悬浮速记按钮。
- 按钮拖动后不会进入底部导航或屏幕安全区，点击不会误触拖动。
- 速记保存、编辑器草稿恢复/丢弃、详情编辑返回、锁屏重试和撤销删除均有 widget 或单元测试。
- 导入备份执行前必须出现确认界面，永久删除确认必须展示附件影响。
- `flutter analyze` 无问题，全部 Flutter 测试通过。
